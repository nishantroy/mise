# Mise: build notes

Decisions and deviations from `PLAN.md`, plus checks that need a real device.

## Decisions and deviations

- **Generated project is not committed.** `Mise.xcodeproj` is in `.gitignore`; run `xcodegen generate` after cloning or after editing `project.yml`.
- **Info.plists are hand-written** (`App/Info.plist`, `ShareExtension/Info.plist`) rather than generated by XcodeGen, so the `AppGroupID`, export-compliance and extension keys are visible in the repo.
- **RecipeKit uses `swift-tools-version: 6.2`** (needed for `.iOS(.v26)` in `platforms`), Swift 6 language mode. Tests use Swift Testing (`import Testing`).
- **A `MiseUITests` target was added** to `project.yml` (the amendments ask for XCUITests); it is wired into the `Mise` scheme's test action.
- Build output goes to `build/` (ignored), via `-derivedDataPath build/DerivedData`.

- **Fixtures (M1).** Serious Eats returned HTTP 402 to curl, and NYT Cooking is paywalled, so the five fixtures are: The Woks of Life (`@graph`, Shaoxing wine), Indian Healthy Recipes (Indian blog, `@graph` + `HowToSection`), BBC Good Food (top-level object, `ImageObject`), RecipeTin Eats (`HowToSection`), and Wikibooks Kung Pao Chicken (no JSON-LD). Each was trimmed to `<title>`, `og:` meta tags and the JSON-LD blocks (Wikibooks: the article body), with a comment giving the source URL.
- **Text fallback headings.** Besides "Instructions / Directions / Method / Steps" the fallback also accepts "Preparation", "Procedure" (Wikibooks) and "How to make". Sub-headings inside the ingredient list (`<h3>`, or pasted lines ending in ":") are skipped rather than parsed as ingredients. When the page has heading tags, steps stop at the next heading; for pasted text they stop at a "Notes / Tips / Nutrition…" line.
- **Text fallback title** is `og:title` or `<title>` with a trailing " - Site name" removed. Wikibooks therefore gives "Cookbook:Kung Pao Chicken"; good enough, and the user can rename. Servings are detected from "Serves N / Servings N / Makes N" above the ingredients; time is not parsed in the fallback.
- **Ingredient names keep their original case** ("Shaoxing wine"), not lowercased as in the plan's example; matching lowercases internally.
- **Notes from the JSON-LD path:** none (`notes` stays empty); section names in `HowToSection` are dropped and their steps flattened.
- **Cuisine** with several values is joined ("Asian, Indian").
- **Quantity formatting:** cooking units use ⅛ ¼ ⅓ ½ ⅔ ¾ glyphs (values ≥ 10 round to whole numbers); g/kg/ml/l/oz/lb use decimals, rounding to the nearest 5 above 100.
- Extra units beyond the plan's list: dash, slice, stalk, sprig, bunch, handful, inch, piece, packet, fl oz.

- **Catalog size (M2).** `ingredients.json` has 204 entries and `swaps.json` 120 (the plan said ~150 / ~60); more coverage across the owner's cuisines made the swap tables more useful. Both are checked by a test that every swap id exists.
- **Catalog matching does not strip prep words before matching.** Whole-word, longest-alias containment already ignores extra words, and stripping "chopped"/"crushed" would break aliases like "chopped tomatoes" (canned) and "crushed red pepper". Prep words *are* stripped when building pantry keys for names the catalog doesn't know. Matching also folds diacritics and applies a light singular rule ("onions" → "onion") to both sides.
- **One review item per ingredient.** Priority: conflict > dislike > missing > have (fine) > specialty/rare ("Do you have X?"). The spicy check is not a separate card when another flag applies; instead every item carries `suggestedScale = 0.5` for spicy ingredients when `spiceLevel <= 1`, and an otherwise-fine spicy ingredient gets a `tooSpicy` card.
- **Swap ranking bonuses need at least one component**, so "Leave it out" never gets the +3 "all in pantry" bonus vacuously. For conflict, dislike, missing and ask cards, "Leave it out" is appended after the top 3 when the table has it.
- **Step rewriting** masks longer catalog aliases that contain the target ("dark soy sauce" while swapping "soy sauce"), replaces longer aliases first, and capitalises the new name only at the start of a sentence. Leave-it-out (remove) edits don't touch steps.
- **Swapped-in ingredient names are the catalog display name** (first alias, lowercase, e.g. "dry sherry").

- **Feedback clause splitting (M3).** Sentences split on `. ! ? ;` and newlines; clauses on commas and "but / so / then / because", and on "and" only when a new clause follows ("…breast and it was too salty"), so "skipped the cilantro and sesame oil" stays one list.
- **"Too salty" with several salty ingredients** produces one edit per ingredient (salt, soy sauce, dark soy, tamari, fish sauce). So the plan's mixed sentence gives exactly 3 edits on a recipe with one salty ingredient (tested on a simple recipe and on the RecipeTin chow mein fixture); on a recipe with both soy sauce and "salt to taste" it gives 4 (scale + "Use less salt than last time" note, per amendment 6). Taste rules with no matching ingredient fall back to a note.
- **Removals and scalings are all-or-nothing over a list**: every item must match a recipe ingredient, otherwise the clause becomes a note (covers amendment 11 for "no problem" etc.). Pure filler ("no changes", "nothing", "ok") is dropped rather than saved as a note.
- **"added X" where X is already in the recipe** (and X has no amount) becomes "more X" (×1.25).
- **Edit summaries** show amounts where known: "Less soy sauce: 2 tbsp → 1 ½ tbsp".

- **DESIGN.md was added mid-build** (owner request, arrived during M4). It is committed with M4, the first milestone that uses it. All colour tokens are colour sets in `App/Assets.xcassets/Mise/` (light + dark), exposed as `Color.mise.*`; spacing, radii, fonts and the shared components (`MiseCard`, `SectionCard`, `RecipeCard`, `Chip`/`ChipGroup`, `PrimaryButton`/`SecondaryButton` + button styles, `Badge`, `ReviewCard`, `EmptyState`, `PageDots`, `FlowLayout`) live in `App/Theme/`. `AccentColor` and `LaunchBackground` mirror the `accent` and `background` tokens.
- **Contrast (checked with a script against the hex values):** every text/fill pair in the spec passes 4.5:1 except `accent` text on `surfaceSunken` in light mode (4.37:1), which the spec prescribes for secondary buttons; their label is 17pt semibold, which qualifies as large text (3:1). Badges use a 12% tint fill instead of the spec's 15% so `herb` text on it reaches 4.65:1 (15% gives 4.46:1).
- **Preference controls are chips everywhere** (diet, avoid, spice level, cuisines, weeknight time), in onboarding and Settings, instead of a Picker/Slider, so both screens share one set of editors. Household size is a system Stepper.
- **Onboarding keeps the plan's 4 pages** (diet + avoid; dislikes + heat; cuisines + time + household; pantry), so a page can hold two or three short questions rather than strictly one.
- **Pantry "cards"** are inset-grouped List sections with `surface` rows on the cream background, which keeps native swipe actions; Have/Missing headers are serif.

- **Clipboard (M5).** The link field is not prefilled from the clipboard on appear (amendment 2): reading `UIPasteboard.general.url` triggers the paste prompt. A `PasteButton` fills the field in one tap instead. Share-extension URLs (M8) do prefill it.
- **Stubbed network in UI tests.** `-uiTesting` uses a separate store file (`MiseUITest.store`), `-resetData` deletes it first, and `MISE_STUB_PAGES` (JSON of URL → HTML, built by the UI test from the RecipeKit fixtures that are copied into the UI-test bundle) swaps in `StubRecipeFetcher`. `RecipeFetching` and the fetcher are injected through the SwiftUI environment.
- **Revision 1 on import** is always recorded: "Imported" or "Imported: Swapped Shaoxing wine for dry sherry; …". `originalData` is the recipe as parsed, before swaps, so "Reset to original" also undoes import-time swaps.
- **Spicy-only cards** default to "Use half" switched on; other cards offer it as an off-by-default toggle when the user likes mild food. A chosen swap wins over halving.
- **"Do you have X?" → Yes** writes `have` and collapses the card; **No** writes `missing` and reveals the swaps in place. The review list is computed once when the screen opens, so answering doesn't reshuffle the cards.
- **Recipe detail landed in M5** (needed to verify the saved swap); M6 adds the adjust flow.

- **Adjust flow (M6).** Selected quick chips (except "Perfect") and the free text are joined into one feedback string for the assistant. "Perfect" isn't parsed; it sets the rating to thumbs-up if no thumb was chosen. Feedback that was typed but never run through "Suggest changes" (or changed since) is saved as a note, so nothing is lost. Every save bumps `timesCooked` and records a revision ("Cooked it" or "Cooked it: …"), even with no edits. If the assistant throws, the view falls back to the rules.

- **Foundation Models (M7)** follows the installed iOS 26.5 SDK: `SystemLanguageModel.default.availability` (`.available` / `.unavailable(.deviceNotEligible | .appleIntelligenceNotEnabled | .modelNotReady)`), `LanguageModelSession(instructions:)`, `respond(to:generating:options:)` with `@Generable` `EditPlan`/`GeneratedEdit` (kind is a `@Generable` enum; non-optional fields with ""/1.0 defaults; `factor` guided to 0.25…3.0, at most 6 edits) and `SwapPlan`. Temperature 0.2 for edits, 0.3 for swaps. Prompts send ingredients (≤30) and steps (≤10, truncated), never page HTML.
- **Mapping model output lives in RecipeKit** (`ProposedEdit`), so it is unit-tested with `swift test`: names map back through the same matcher as the rules; unknown ingredients, no-op or absurd factors and empty notes are dropped; one edit per ingredient; "add X" where X is already in the recipe becomes "more X"; a split "1 tbsp" + "lime" is recombined (seen in the simulator).
- **If the model returns nothing usable**, the rules' edits are used. Any thrown error (guardrail, context window, decoding…) is logged with `os.Logger` and falls back to the rules silently. Prompts and outputs are logged in DEBUG builds (subsystem "Mise", category "FoundationModels").
- **The simulator here exposes the model** (it reports `.available`, via the host Mac), so `AssistantUITests.testModelPathWhenAvailable` runs the real model end to end; it skips itself where the model is unavailable. For "it was a bit flat, so I finished it with lime and more oyster sauce" on the chow mein fixture it proposed "More oyster sauce: 1 ½ tbsp → 1 ¾ tbsp" and "Add 1 tbsp lime". (The rules also catch this sentence via "finished it with"; they miss phrasing like "a bit flat" on its own.) All other UI tests launch with `-forceRules`, which is how the rules-only path is tested (amendment 12).
- **Availability is re-read when the app becomes active**, so turning Apple Intelligence on or off is picked up without relaunching. `-resetData` also clears the force-rules default.

- **Share extension (M8).** `PendingImports.swift` is compiled into both targets and reads the group ID from each bundle's `AppGroupID` Info.plist key. The extension accepts the first `public.url` attachment, falling back to a link found in shared plain text, and shows "Saved. Open Mise to finish importing." for about a second before completing (a plain UIKit card: the extension has no asset catalog, so it uses system colours rather than the theme). The app drains the queue each time it becomes active, but only once onboarding is done, and shows one import sheet per URL in turn. `-enqueueImport <url>` simulates the extension for UI tests.
- **The real share flow was driven in the simulator**: `SafariShareUITests` opens https://example.com in Safari, uses More → Share → Mise, returns to the app and checks the import sheet holds that URL. It passed here. It needs network access and skips itself when Safari's UI doesn't match (Share lives under the "More" menu in iOS 26 Safari).
- **UI-test helper hardening:** `completeOnboarding` taps Continue until the last page appears, because taps during the page animation were occasionally dropped.

## Manual checks (owner, on a device)

- **M7 on a device with Apple Intelligence on:** import a recipe, cook it, and try free-form feedback (e.g. "it was a bit flat, so I finished it with lime and more fish sauce", "the sauce was too thin, I simmered it uncovered longer"). Check the proposals are sensible and that unticking works. Then turn Apple Intelligence off (Settings → Apple Intelligence & Siri) and return to Mise: Settings should say the rules are active and why, and the same flows should work with no error shown. Also try the "Use built-in rules only" toggle.
- **M7 swap gaps:** on device, answer "No" for a specialty ingredient that has no bundled swaps (allspice, chili oil, black bean sauce, rice noodles, bulgur, semolina, coconut aminos); the model should fill in up to 3 swaps, favouring pantry items. With the model off, such cards offer only "Keep original".
- **M8 on a phone:** in Safari open a recipe page → Share → Mise (enable it under "More"/Edit Actions the first time) → "Saved. Open Mise to finish importing." → open Mise → the import screen shows that URL → Import. Also try sharing two pages before opening Mise (two sheets in turn). On a device this also confirms the App Group is provisioned for both bundle IDs; in the simulator the group works without provisioning.
